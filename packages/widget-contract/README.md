# Контракт виджетов

Эталон для форка на Node.js 24+. Пакет превращает декларацию страницы в автономный HTML и модель нативного экрана. Запускайте команды из корня репозитория.

```bash
node --test packages/widget-contract/contract.test.mjs
node packages/widget-contract/render.mjs examples/coffee/page.json > coffee.html
node packages/widget-contract/release.mjs examples/coffee/page.json
```

В примере «Зерно» есть обложка, меню с ценами, часы работы и заказ по почте. Откройте `coffee.html` в браузере. Кнопка обложки ведёт к меню. Для заказа в примере стоит демонстрационный адрес `orders@example.com`.

## Как расширить форк

Правила конкретного бизнеса храните в `business/extensions/`. В примере [программы лояльности](../../business/extensions/loyalty/README.md) предприниматель меняет число баллов за заказ. Адаптер рассчитывает условия награды, создаёт блок `forma.text@1` с постоянным ID и передаёт обычный черновик в общую сборку. Веб и установленные приложения уже умеют его показать.

Для другого предложения используйте тот же способ:

1. Дайте исходному формату проекта собственное имя и версию. Проверьте входные поля до расчёта.
2. Составьте из них один или несколько поддерживаемых блоков со стабильными ID. Проверьте результат через `validatePage`, включите его в черновик и вызовите `makeRelease`. Эти функции доступны из `contract.mjs`.
3. Сохраните тест с прежним поколением приложения. Генератор проверяет браузерное поколение 2 и поколения 1 и 2 установленных приложений. Форк может передать собственную матрицу вторым аргументом `makeRelease`.

Если функция требует нового способа отображения или действия, спроектируйте контракт типа, его версию и клиентские реализации. В эталонном ядре перечень встроенных типов фиксирован. Расширение общего перечня оформляется отдельным изменением схемы, реестров и рендереров с выпуском нужных клиентов. Старые версии могут показывать зарегистрированный `fallback` для необязательного виджета. При отсутствии такой замены они пропускают его. Отсутствие обязательного типа или внутренней цели перехода останавливает выпуск для соответствующей платформы.

Параметры компоновки наследуются от `phone` к `tablet` и `wide`. Ширина указана в долях 12-колоночной сетки.

## Границы примера

`nativeViewModel` возвращает дерево примитивов для React Native. Хост-приложению потребуется реализовать компоновку, прокрутку к разделу, почтовую ссылку и управление фокусом. Для нативного тестового релиза нужны iOS/Android-сборки. Действия в контракте ограничены внутренним переходом и электронной почтой.

`examples/coffee/release.json` содержит проверяемый снимок черновика. SHA-256 считается по JSON с отсортированными ключами объектов. Копия не меняется при последующем редактировании страницы. При загрузке из внешнего источника требуются аутентификация и проверка подписи издателя. В рабочей системе ревизии хранятся отдельно от указателя активной версии, с политикой неизменяемой записи.

Для интеграции с Payload понадобится сериализатор опубликованных полей и отдельный авторизованный доступ к черновикам. Установщик VPS, рабочие процессы агентов, управление ключами и магазины приложений находятся за пределами этого исполняемого примера.
