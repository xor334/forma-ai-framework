# Модули бизнеса

Из корня форка выполните `npm run module:new -- inventory "Учёт остатков"`. Шаблон создаёт автономный сервис с проверкой готовности, собственным Dockerfile и локальным тестом. По умолчанию список запрашиваемых сетевых соединений пуст.

```sh
npm run module:check
npm run module:test -- inventory
npm run check:plan
docker build -t inventory:dev business/modules/inventory
```

Идентификатор каталога совпадает с `id` в `module.json`. Поместите интерфейсы в `contracts/`, миграции своего пространства в `migrations/`, проверки в `tests/`, описание модуля в `README.md`. Схема манифеста определяет роли, поля настройки, тип модуля, предоставляемые контракты, зависимости и запрошенные сетевые правила. Значение `secret-ref` описывает поле со ссылкой на секрет. Рабочие значения хранятся в окружении установки.

Поле `provides` может содержать `sql:stock@1`. Потребитель указывает в `requires` объект `{"module":"inventory","contract":"sql:stock@1"}`. Такой же формат применяется к API, командам, событиям, инструментам MCP и библиотекам. Проверка реестра отклоняет отсутствующего поставщика или версию. Реальные выдача SQL-прав, сетевой доступ и установка модуля в рабочую среду относятся к отдельному этапу выпуска.

У модуля есть собственная сборка и обязательный вход для контрактного теста `tests/contract.test.mjs`. Для реализации на другом языке сохраните эти внешние соглашения: Dockerfile собирает выбранный runtime, тест вызывает его публичный интерфейс или запускает его штатные проверки. Добавляйте реальные проверки поведения рядом с тестом готовности. Шаблон сам по себе не подключает сервис к веб-пилоту.
