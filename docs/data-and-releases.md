# Данные проекта, выпуск и восстановление

Владелец контролирует репозитории, хранилища и ключи. Релиз связывает конкретные версии кода, контента и ресурсов. Его можно воспроизвести при выключенном редакторе.

| Хранилище владельца | Что хранится |
| --- | --- |
| Git | Компоненты, шаблоны сайта и бота, миграции, инфраструктурные файлы, зафиксированные зависимости. Коммит определяет версию исходников. |
| PostgreSQL + pgvector | Права, версии страниц и блоков, конфигурация диалогов, задачи, сообщения, знания с индексом, журнал релизов. Черновики и опубликованные версии имеют отдельные указатели. |
| Объектное хранилище | Иллюстрации, вложения, оригиналы документов, экспорты и резервные копии. Ссылки включают идентификатор версии или контрольную сумму. |
| OCI-реестр | Образы приложений и исполнителей, адресуемые по digest. Владелец выбирает локальный или внешний реестр. |
| Артефакты мобильного CI | Подписанные сборки iOS и Android, номера build, runtimeVersion и контрольные суммы; доставка из учётных записей владельца через TestFlight и Play. Исходники приложения в Git, ключ подписи хранится отдельно от артефактов. |
| ОС и хранилище секретов | Менеджер служб запускает компоненты. Секреты монтируются только нужным процессам из менеджера секретов или защищённых файлов хоста. В конфигурации проекта хранятся ссылки на секреты. |

## Минимальная схема

| Сущности | Связи и обязательные ограничения |
| --- | --- |
| Организация, проект, участник, разрешение | Каждый объект принадлежит проекту. Внешние ключи и политики доступа проверяют границу проекта. |
| Страница, блок, версия контента | Постоянный ID блока связывает чат, содержимое и компоновку для каждого размера экрана. Сохранение проверяет ожидаемую базовую версию. |
| Источник, версия документа, фрагмент | Ссылка на оригинал, категория доступа, статус публикации, позиция фрагмента и версия модели индекса. |
| Диалог, сообщение, задача, предложение, одобрение | Диалог привязан к посетителю, проекту, блоку или внутренней задаче. Одобрение указывает хеш предложения и автора решения. |
| Входящие события, исходящие операции, задания, релизы | Уникальны ID входящего события в рамках установки канала и ключ операции в рамках проекта. Манифест релиза фиксирует Git SHA, образ, версию контента, манифест медиа и версию схемы. |

## От сообщения до релиза

1. Приёмник одной транзакцией записывает событие и задание. Повторная доставка возвращает прежний результат. Исполнитель арендует задание на ограниченное время, продлевает аренду и сохраняет контрольные точки. Изменения одного диалога обрабатываются по порядку.
2. Агент записывает предложение относительно базовой версии. При параллельной правке координатор возвращает конфликт и показывает затронутые блоки. Сборка по зафиксированным входам формирует образ и предпросмотр. После тестов владелец одобряет манифест, проверенный в предпросмотре.
3. Желаемая версия и команда публикации попадают в журнал одной транзакцией. Исполнитель сверяет фактическую версию, поднимает новую, проверяет готовность и переключает трафик. После переключения проверяет публичный маршрут и при сбое возвращает прежнюю версию. Исходящие ответы бота также проходят через журнал операций. При неопределённом результате отправки канал требует сверки, чтобы повтор не создал второе сообщение.
4. Откат возвращает предыдущий манифест. Новые обращения клиентов, аналитические события и история задач сохраняются. Миграции БД остаются совместимыми с двумя соседними версиями приложения. Для несовместимой миграции готовится отдельный план восстановления данных. [Спецификация OCI](https://github.com/opencontainers/image-spec/blob/main/descriptor.md)

## Резервные копии и самостоятельный перенос

Владелец задаёт допустимую потерю данных и время восстановления. Базовая копия PostgreSQL и архив WAL хранятся вне исходного VPS. Отдельно копируются Git, объекты, нужные образы и защищённый комплект восстановления секретов. Проверка на чистом VPS включает запуск сайта и бота, открытие медиа, тест прав на знания и доставку тестового сообщения в отдельный канал. [Восстановление PostgreSQL на момент времени](https://www.postgresql.org/docs/current/continuous-archiving.html)

Для самостоятельной доработки владелец клонирует Git, экспортирует снимок данных и манифест релиза, переносит объекты и переназначает секреты. Новый экземпляр сначала запускается с тестовыми каналами. После проверки владелец переключает домен и передаёт приём сообщений новому экземпляру. Такой перенос не требует аккаунта в центральном сервисе.
