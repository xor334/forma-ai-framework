# Forma AI · архитектура базового репозитория

Этот репозиторий предназначен для двух команд. Автор платформы выпускает общие исправления. Предприниматель забирает историю к себе, добавляет бренд и бизнес-логику и выпускает свою версию на своём VPS. Сервер автора платформы для работы клиентского проекта не требуется.

**Состояние этой поставки — 0.1.0, архитектурный прототип.** В репозитории работают инициализация бизнес-профиля, расширение программы лояльности, проверка контрактов виджетов, HTML-рендер демонстрационной страницы и тест переноса обновления базы в изменённый форк. Документация задаёт требования к реализации Payload, React Native, ботов, защищённого агента и промышленного деплоя. Установка этого архива сама по себе их не запускает.

## Попробовать без сервера и ключей

Распакуйте ZIP и откройте терминал в каталоге с этим README. В архиве есть Git-история и ветка `main`. Нужны Node.js 24 и Git. Для локального примера устанавливать npm-пакеты не требуется.

```sh
git log -1 --oneline
npm test
npm run init:project -- sever-coffee "Кофейня Север"
node packages/widget-contract/render.mjs examples/coffee/page.json > coffee.html
node packages/widget-contract/release.mjs examples/coffee/page.json
```

Откройте `coffee.html` браузером. Команда инициализации создаст `business/project.json` один раз. Это публичные настройки проекта. Рендер читает демонстрационную страницу из явно указанного JSON. Создание бизнес-профиля и публикация сайта — разные операции.

## Кому принадлежит какая часть

| Зона | За что отвечает |
| --- | --- |
| Автор базы | Общие пакеты, интерфейсы виджетов и каналов, исправления безопасности, миграции, политика совместимости, журнал изменений. |
| Предприниматель | Собственный репозиторий, домен, VPS, доступ к моделям, реестр образов и аккаунты магазинов. Назначает сотрудников, выбирает состав каналов и принимает релизы. |
| Бизнес-проект | Бренд, виджеты и интеграции конкретного бизнеса в `business/`. Данные клиентов, ключи, дампы и история чатов остаются в инфраструктуре предпринимателя. |

## Карта репозитория

| Путь в этой поставке | Содержимое |
| --- | --- |
| `business/` | Место для именованных настроек и расширений форка. Собственный профиль создаётся из командной строки. |
| `packages/widget-contract/` | Проверяемый контракт, правила совместимости и пример рендеринга. |
| `examples/coffee/` | Страница для общей контрольной проверки. Бизнес может скопировать её в свой каталог, сохранив общий пример для будущих тестов. |
| `scripts/`, `.github/workflows/` | Инициализация проекта, локальные проверки и CI, который не требует доступов к проду. |
| `docs/` | Архитектурные решения, границы доступа и эксплуатация. |

В целевой структуре `apps/web/` обслуживает публичный сайт, `apps/studio/` — кабинет Payload, API и холст, `apps/mobile/` — приложения iOS/Android, `services/worker/` — задачи и ботов. В `infra/` появятся отдельные профили окружений и конфигурация исполнения. Эти каталоги добавляются вместе с работающей реализацией. Пакеты исходников и контейнеры имеют разные границы: веб, кабинет и рабочие процессы можно выпускать из одной кодовой базы под разными учётными данными.
