# Forma AI

Forma AI задаёт архитектуру для модульных бизнес-систем, которые владелец развивает в своём репозитории с помощью VS Code, Claude Code, Codex или другого инструмента. Фреймворк поставляет шаблон сервиса, контракты и проверяемые ограничения. Прикладную логику определяет владелец. Работающие модули живут независимо от выбранной среды разработки.

**Начать с собственного модуля.** На Node.js из `.nvmrc` выполните `npm ci`, затем создайте и проверьте сервис без бизнес-логики.

```sh
npm run module:new -- inventory "Учёт остатков"
npm run module:check
npm run module:test -- inventory
npm run check:plan
```

**Что доступно сегодня.** Автономные модули собираются отдельно. Веб-пилот версии 0.2.0 обслуживает один бизнес и одну редактируемую страницу. Его студия поддерживает ручные правки, предложения ИИ, предпросмотр, утверждение выпуска и просмотр обращений. В архитектурной спецификации указано, какие функции общей админки, MCP и сетевой изоляции ещё предстоит реализовать.

[Полная архитектура и состояние реализации](docs/modular-framework.md) · [Контракт и команды для форка](business/modules/README.md)

## Локальная демонстрация

Из корня проекта на Node.js 24.22.3 выполните

```sh
npm ci
npm run demo
```

Команда запускает временную PostgreSQL, публичный сайт, студию и исполнителей на localhost. Адреса, демонстрационный email и одноразовый пароль появятся в терминале. **Ctrl+C завершает демонстрацию и удаляет её временные данные.** Для постоянной установки используйте Compose.

1. Войдите в студию, выберите блок и измените текст или размеры. Блоки можно добавлять, перемещать и возвращать к прежнему состоянию кнопкой «Отменить».
2. В разделе «Выпуски» подготовьте предпросмотр. Проверьте текст и медиа, затем нажмите «Выпустить этот снимок». Обновите состояние выпуска.
3. Откройте публичный сайт, отправьте заявку и найдите её в разделе «Обращения». После второго выпуска станет доступен возврат к предыдущей версии.
4. Для предложений ИИ задайте `MODEL_ENDPOINT` (полный адрес chat completions), `MODEL_NAME` и при необходимости `MODEL_KEY` в окружении перед запуском. Поручение в свойствах блока передаёт модели выбранный блок и текст задачи. Без профиля задания ждут исполнителя.

## Разработка с ИИ

- **Изменение контента.** У задачи есть ID блока, базовая ревизия и автор. Предложение содержит поле и новое значение. Владелец видит разницу и принимает решение. При изменении того же свойства студия показывает конфликт. Независимые ручные правки сохраняются.
- **Изменение кода.** Команда ниже передаёт выбранной модели текст задачи и только перечисленные файлы одного модуля или доверенного адаптера из `HEAD`. Результат — обычный патч в stdout с базовым SHA. Его можно проверить в рабочей ветке, передать на review и прогнать через CI. Нужен настроенный профиль модели.
- **Совместная работа.** После внешней проверки первого выпуска становятся доступны маркетолог, аналитик и поддержка. Раздел «Команда» показывает задания, результаты и передачи. Источники поддержки ограничены действующими публичными статьями, аналитика получает агрегаты за неделю. Для одной цепочки действуют дедлайн и ограничение глубины.

```sh
npm run --silent ai:propose -- 'Добавь проверку на граничное начисление баллов' \
  business/extensions/loyalty/loyalty.mjs \
  business/extensions/loyalty/loyalty.test.mjs > /tmp/forma-change.patch
git apply --check /tmp/forma-change.patch
```

## Собственный бизнес-проект

Сохраните Git-историю базы при создании своей копии. Команда `npm run init:project -- my-business "Название бизнеса"` создаёт публичный профиль. Доверенные расширения страницы регистрируются в `business/extensions/index.mjs`. Включайте их декларациями в `business/extensions.json`. Массив по умолчанию пуст. Для примера лояльности можно поместить объект из `business/extensions/loyalty/offer.json` в этот массив. Компилятор применяет настройки к копии черновика при подготовке выпуска. Адаптер становится частью проверяемой сборки проекта.

| Путь | Ответственность |
| --- | --- |
| `apps/web` | Next.js, опубликованный сайт, заявки, веб-чат и API v1 |
| `apps/studio` | React-редактор, аутентификация Payload, роли, утверждение, обращения и знания |
| `apps/mobile` | Expo / React Native, модели экранов iOS и Android, локальный кэш последнего снимка |
| `packages/widget-contract` | Схемы страниц, миграция раскладки, совместимость каналов и рендеринг |
| `packages/runtime` | Прикладные команды, ревизии, снимки, медиа, доступ и работа с PostgreSQL |
| `services/worker` | Предложения модели, команда, исполнитель выпуска, адаптер Telegram и поиск |
| `infra` | Compose, HTTPS, изолированные учётные данные, сборка кода, сохранение и восстановление |

## Проверки

`npm run test:critical` проверяет базовые сценарии пилота на временной PostgreSQL при каждом PR и обновлении main. `npm run check:plan -- origin/main` показывает затронутые модули и группы проверок. Для полной проверки используйте `npm run check:plan -- --all` и команды ниже. Отличия между планом проверки и независимым выпуском описаны в [архитектуре](docs/modular-framework.md#качество-стоимость-и-выпуск).

```sh
npm test
npm run typecheck
npm run build
npx playwright install chromium webkit
npm run test:pilot
```

`npm test` запускает контракты, проверку форка и интеграционные сценарии во временной PostgreSQL. `test:pilot` использует собранные приложения и проверяет работу владельца через браузеры на ширинах 390, 768 и 1440 px. Для проверки с Docker выполните `npm run test:compose`. Этот сценарий создаёт две временные установки с приватным S3, восстанавливает снимок и проверяет опубликованную страницу, файл и контрольную заявку. Временные контейнеры и тома принадлежат отдельным Compose-проектам.

Для мобильного клиента используются собственный lock-файл и переменная `EXPO_PUBLIC_FORMA_URL` с публичным HTTPS-адресом сайта. Из каталога `apps/mobile` выполните `npm ci` и `npm run bundle` для сборки JavaScript iOS и Android. Нативные сборки, идентификаторы приложений, подпись и доставка в тестовые треки принадлежат владельцу бизнеса.

Инструкция для VPS, настройки интеграций, решения по совместимости и границы пилота приведены в [руководстве по эксплуатации](docs/operations.md).
