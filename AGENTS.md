# Разработка Forma AI

Пожелания владельца о разрешениях и границах задачи применяются ко всей работе с этим проектом.

## Работа в репозитории и форках

1. Определите модуль, требуемое поведение и проверяемый пример владельца. Откройте [архитектуру и критерии готовности](docs/modular-framework.md) и манифест модуля.
2. Для нового сервиса используйте `npm run module:new`. Бизнес-логику, миграции, настройки и тесты держите в каталоге модуля. Версионированные межмодульные зависимости указывайте в `requires`. Для предложений через `ai:propose` выбирайте один модуль.
3. Для изменения роли, прямого чтения SQL, сетевого маршрута или инструмента MCP укажите запрошенное полномочие. Его фактическая выдача выполняется в целевой установке отдельно. Промышленные секреты и полномочия выпуска остаются у оператора.
4. Перед сдачей выполните `npm run module:check`, `npm run check:plan`, обязательный `npm run test:critical` и проверки затронутых модулей. Стандартный CI использует локальные данные и фикстуры моделей. Укажите затронутые контракты, что тестировалось и какие артефакты требуют выпуска.

## Точки входа

- Код и интеграции конкретного бизнеса находятся в `business/`. Адаптер получает копию страницы и декларацию, возвращает проверяемые блоки. Подключение проходит через `business/extensions/index.mjs` и `business/extensions.json`.
- Версии формата страницы и договорённости каналов находятся в `packages/widget-contract/`. До изменения контракта проверьте сохранённый выпуск кофейни и выдачу для предыдущих поколений клиентов.
- Серверные команды для редактора, событий и выпусков находятся в `packages/runtime/`. Процессы используют отдельные роли PostgreSQL. Новые полномочия оформляются миграциями в `infra/migrations/`.
- Студия принимает ручные и предложенные правки через одни и те же проверки. Агент возвращает предложение с базовой ревизией. Решение владельца хранится отдельно.
- Команды проверки проекта и порядок запуска описаны в README. Для изменений размера, прав или выпуска предусмотрены проверки прежнего формата, конфликтов, повторов и восстановления.
- Укажите в результате изменившееся поведение, запускавшиеся проверки и условия для испытаний на инфраструктуре владельца.
